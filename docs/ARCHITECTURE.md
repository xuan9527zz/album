# 架构与关键决定

## 数据与边界

浏览器从 Supabase Auth 取得 access token。Worker 使用 Supabase `getClaims` 验证签名、发行者、受众和有效期，再由数据库 RPC 检查启用名单及照片归属。原有 `album_action` 保持上传、修改、删除只限所有者；新增 `album_v2_action` 只向启用成员提供共享照片的读取及下载，分享开关和个人资料修改仍只由本人操作。Worker 持有后台密钥，前端无法写入数据库表。`authenticated` 的直连 RLS 仍只可读取本人记录；共享访问仅走已鉴权的 Worker。`anon` 读不到业务数据。`upload_sessions`、`upload_items`、`storage_budget` 都只供 service role 使用。

初始数据库迁移为 `202610120001_album.sql`；`202610130001_shared_album_profiles.sql` 添加默认关闭的 `is_shared`、成员头像字段和受控共享 RPC；`202610130002_trash_batch_search.sql` 添加私有最近删除、批量操作和服务端筛选。既有照片不会自动进入共享相册或最近删除。删除将状态改为 `trashed` 并记录时间，普通读取、共享读取、原件下载和直连 RLS 都排除该状态；本人可在 30 天内恢复，定时维护到期后转入既有的已知对象清理流程。被删除照片仍计入容量，恢复后维持原共享状态；旧会话清理不能意外将其恢复为可见。批量更新在单个数据库事务中逐一核验所有者，最多 50 张，任何一个越权或无效目标都使整批失败。筛选在数据库执行并保留稳定游标分页。取消共享后不再签发新链接，先前签发的短时链接仍需等有效期结束。昵称和头像仅由本人修改；头像在浏览器裁为小尺寸 JPEG 并限制在 90 KB data URL 内，保存在个人资料表。四人限制在数据库触发器中执行。照片按拍摄日期和上传时间稳定分页；缺拍摄日期才使用上传日期排序。EXIF 本地时间和 UTC 偏移分开存储，不在未知时区时推算 UTC。上传时读取的原始元数据保存在 `source_metadata`，显示信息可编辑但不改变文件。

## 文件链路

1. 客户端对原文件分块计算 MD5 和 SHA256；后端在同一事务中核验名单、幂等键与项目容量，预留所需字节并生成随机对象 key。
2. R2 S3 签名只允许短时 `PUT` 指定 key，绑定 Content-Type、Content-MD5、Content-Length、`If-None-Match: *`。浏览器无法手动设置 Content-Length，由文件 Blob 请求自动产生。重放旧 PUT 对已有对象应返回 412，不能覆盖已提交原件。
3. 上传后 Worker 使用 HEAD 核验大小、类型和单次 PUT 的 MD5 ETag，再用小范围 GET 检查内容签名。只有完成核验，数据库事务才把预留用量转为已保存用量并登记资产。
4. 浏览器另行生成预览和缩略图，分别上传。HEIC 解码失败时原件仍可下载，详情提供预览补传。补传新的浏览版本时旧版本保留计费，直到到期清理确认旧对象已删。

该实现使用 R2 文档列出的有条件 `PutObject`，取代计划书的 staging + 复制。真实 R2 的合成素材冒烟测试已验证 `If-None-Match` 重放返回 412、Content-MD5 校验和下载 SHA256 一致；真实 iPhone 网络仍需另行验收。[R2 S3 兼容说明](https://developers.cloudflare.com/r2/api/s3/api/)和[预签名 URL 说明](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)是核验依据。

签名有效期和已批准 key 记录于 `upload_items`。取消或删除立即停止新链接，但等待所有旧 PUT 授权过期加 60 秒后才清理对象、释放预算。清理只触碰数据库已登记的 key，可重试，且先删除 R2 再更新账本。若数据库更新失败，下次重试再次删除同 key 后收敛。项目默认预算 8 GB、提醒 6 GB；这是应用限额，不是供应商账单硬上限。预留、已保存与旧浏览版本均计入项目容量。

Worker 给缩略图和预览图签发短时 GET；原件下载需独立请求。签名 URL 不写入数据库或日志。R2 对象通过 `Cache-Control: no-store` 保存，PWA Service Worker 只缓存同域、无查询参数、白名单里的公开静态资源。浏览器和 R2 的真实缓存行为仍需云端验收。

无 VPN 网络中的浏览器通过 Supabase Edge Function 的固定 `/media` 路由读取、上传私有 R2 文件。网关仅接受本账户、本桶的短时签名 URL，流式转发 GET/PUT；R2 仍核验签名和上传校验头。媒体链接使用固定公开 HTTPS origin，避免 Supabase 内部 HTTP 请求地址泄漏给浏览器后遭混合内容拦截。Worker 把列表缩略图授权与列表记录一起返回，把预览图授权与详情一起返回，减少浏览器跨网关请求次数。前端只在当前页面内存中保存缩略图和预览图的 Blob URL，合计上限 64 MiB；退出登录、关闭页面或进程结束后释放，不把私人图片写入 Service Worker、IndexedDB 或 Cache API。超出缓存上限的图片可能在再次打开时重新下载。

`202610130003_shared_comments.sql` 增加只经后台 RPC 访问的共享评论。每条去除首尾空白后最多 30 字，单张最多 200 条；任何启用成员可读和发布，评论作者及照片主人可删除。取消共享、移入最近删除后接口不返回评论；恢复共享后原评论会再次出现。评论只占少量数据库文本空间，不包含图片附件。

## Live 与恢复

相册选择器不能保证提供 Live Photo 配套视频。导入原件文件时，用户明确把静态图与 MOV/MP4 配在一起；也可在已有静态照片详情补视频。没有可靠元数据证明时只标记 `paired_unverified`，第一版不播放或宣称可还原 iOS 原生 Live Photo。

未完成上传在当前账号的 `sessionStorage` 只记会话 ID，不存照片二进制；重新选文件后核对 SHA256 与后台批准项，完成接口重复调用不重复扣量。已存原件但预览失败的照片仍出现在“全部”。刷新登录会话失败时显示错误，不回退到本地演示。退出时中断本页请求并清除会话记录；已经发出的短时文件链接会到期，不声称立即撤销。

## 已知需云端确认的边界

- R2 签名和 `/media` 网关已用合成对象验证；仍需用无 VPN 的真实 iPhone 分别测量图片首次打开、返回缓存、原件上传和下载。
- iPhone Safari 相册选择的格式转换、HEIC 解码、文件名、下载到“文件”App 的结果。
- 四个真实用户和中国大陆直连的首屏、预览、上传速度；云项目空闲、免费额度和费用以当时平台规则为准。

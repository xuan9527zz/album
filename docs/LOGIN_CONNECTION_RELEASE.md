# 登录连接与备用线路（2026-10-15）

成员“如”的账号已确认、已设置密码且仍启用。手机新版提示对应 Auth 请求的连接异常；这不能证明密码正确，也不能直接归因于 VPN。原始域名健康页在该设备显示连接丢失，备用域名显示空白，均不足以确认备用线路可用。

前端保留 Supabase 的规范项目地址、JWT 签发方及既有会话存储键，只替换请求传输。密码登录和安全的 GET 请求在连接失败或 5xx 时尝试既有 Cloudflare Worker；密码错误、未确认、权限拒绝等明确的 4xx 不换线路。JSON 请求有覆盖响应体读取的 10 秒期限。已取消的页面请求不重试。业务写入、改密码、一次性邀请验证和旋转的刷新令牌不由此层自动重发；失败后下一次请求可换线路，刷新重试仍交给 SDK。

Worker 只转发白名单内的公开 Auth API，使用 publishable key，绝不使用 service-role key，也不开放注册或管理接口。源站、方法及请求体大小受限；保留错误代码和 API 版本响应头，不缓存会话响应，不记录邮箱、密码或令牌。

备用线路的业务请求保留原 JWT/RLS 检查。客户端仅将固定账户、固定桶的 R2 签名地址包装到 Worker `/media`；服务端再次验证目标、签名参数和 PUT 的签名头，R2 继续校验签名、MD5、条件写入和过期时间。禁止任意目标转发；不会自动重发上传或创建影集。

新增 `#/connection-check`：仅检查网站资源、登录服务、相册接口和备用线路，结果保留在当前页面，可手动复制；不包含账号、凭据或签名链接。两条线路均不可达时仍须排查设备网络或提供可达的新入口，自动切换不能保证所有地区可连接。

本地验证：74 项单元/数据库/API 测试通过；实际登录表单与 SDK 在 Chrome/WebKit 的六种连接模拟下通过，包括备用登录后刷新保留会话、密码错误不换线路、两条线路均失败的提示。三种浏览器的连接检查界面与重试通过，既有相册流程 15 项通过；本次未启用的三项 HEIC 专项不计为已通过。PWA 预装、更新和恢复检查保持通过。`npm run test:login` 已加入 CI，使用合成凭据和独立测试服务器。

线上发布和真实 iPhone 结果待后续核对。此改动无需数据库迁移。
